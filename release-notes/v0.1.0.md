# anaf-sync 0.1.0

First release, on PyPI as [`anaf-sync`](https://pypi.org/project/anaf-sync/).

```bash
uv tool install anaf-sync
```

## What's in the box

A scheduled local archiver for RO e-Factura invoices, built on
[anafpy](https://github.com/robert-malai/anafpy). ANAF deletes SPV messages
about **60 days** after filing; each run lists the whole retention window,
downloads only what it has not seen before, and files the results on disk.

- **`anaf-sync sync`** — one pass: list → dedupe → download (with retry) →
  write artifacts. Idempotent by construction: a JSON state file remembers
  every message id already archived, so overlapping 60-day windows never
  duplicate work and a crash mid-run loses none of it.
- **Path templates instead of ANAF ids** — `str.format` over the invoice's own
  fields, so an archived invoice lands at
  `2026/07/2026-07-03_FCT-1001_ACME SRL.pdf` rather than under an opaque
  message id. Every substituted value is sanitised for the filesystem, and
  rendered paths stay inside the output root.
- **Artifacts you choose** — `zip`, `pdf`, `xml`, `signature`, `metadata`.
- **`anaf-sync schedule install`** — registers the sync with the platform's own
  scheduler (Task Scheduler, a systemd user timer, launchd). No daemon of ours.
- **`anaf-sync init` / `status`** — a commented `config.toml` and a report of
  where everything lives.
- **Auth is anafpy's** — `ANAFPY_CLIENT_ID` / `ANAFPY_CLIENT_SECRET` plus the
  token store written by `anafpy auth login`. anaf-sync introduces no
  credential storage of its own, so one ANAF login serves the CLI and the
  anafpy MCP server alike.

Runs on Windows, Linux, and macOS. Python **3.12+**.
