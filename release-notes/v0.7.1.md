# anaf-sync 0.7.1 — fereastra Facturi încape din nou pe ecran

Pe Windows, fereastra **Facturi** din 0.7.0 pornea cu o lățime minimă de
1515px — mai mult decât are un ecran de 1366×768 sau 1440×900, deci nu se putea
vedea întreagă și nu se putea micșora. Versiunea aceasta o repară și aduce tot
ce e în [0.7.0](https://github.com/robert-malai/anaf-sync/releases/tag/v0.7.0):
sortarea și filtrarea din capul tabelului, coloanele **De la CIF** / **Pentru
CIF** și panoul de detalii care se pliază singur. /
0.7.0's Facturi window derived a 1515px minimum width on Windows — wider than a
1366×768 laptop, so it could neither be shown whole nor shrunk. That derivation
is now capped. Everything else in 0.7.0 is unchanged.

**Dacă ai instalat 0.7.0 pe Windows, treci pe 0.7.1.** Pe macOS și Linux 0.7.0
se comportă corect, dar 0.7.1 e oricum versiunea de folosit — 0.7.0 nu a apucat
să primească programe descărcabile pentru Windows.

```bash
pip install --upgrade "anaf-sync[tray]"
```

Arhiva nu e afectată în niciun fel: fereastra Facturi doar citește.

## Ce s-a reparat

**Lățimea minimă a ferestrei are acum un plafon.** În 0.7.0 fereastra își
deducea pragul de lățime din coloane — fiecare coloană își ia lățimea din fontul
sistemului, iar fereastra cobora doar până unde coloana *Partener* mai primea
200px. Ideea e bună, dar deducerea nu avea nicio limită de sus: pe Windows
coloanele fixe măsoară 1032px față de 724 pe macOS, deci pragul ieșea 1515px.

Peste 1320px, fereastra nu mai lărgește pragul. Pe un font lat asta înseamnă o
coloană *Partener* mai strâmtă și, la limită, o bară de derulare orizontală —
un compromis mult mai bun decât o fereastră căreia nu-i vezi marginea. Etichetele
din cap se termină acum în „…” când nu încap, în loc să fie tăiate.

**Programele descărcabile pentru Windows sunt din nou aici.** Pasul care le
construiește a picat la 0.7.0 exact pe defectul de mai sus.

## Internal

- **The derived width floor is capped at `MAX_MINIMUM_WIDTH`.** The derivation
  itself was right — a constant floor squeezes Partener hardest on exactly the
  platforms whose font metrics are widest — but it had no ceiling, and a floor
  that outgrows the screen is worse than a squeezed column. A regression test
  installs a deliberately wide application font, checks the columns really did
  inflate, and asserts the floor still fits a small laptop.
- **The test that caught this asserted the wrong thing.**
  `test_window_design_size_is_the_minimum` resized to a hard-coded 1400 to prove
  the window is not fixed-size; on Windows that is *below* the derived floor, so
  the failure read as a resize bug rather than the font difference it was. It
  sizes relative to `minimumWidth()` now.
- **A failed bundle no longer skips the GitHub release.** `github-release`
  waited for `bundle` and *required* it, so one platform's failure left the tag
  published to PyPI with nothing announcing it — three times now (v0.5.0,
  v0.6.0, v0.7.0). It runs on `publish` succeeding and attaches whatever bundles
  built; the run still reports failure, so the gap stays visible and the tag
  re-runnable. This is the PyPI-first ordering's own failure mode, arrived at
  from the other side.
