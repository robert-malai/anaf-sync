# anaf-sync 0.1.4 — one archive key on every platform

## Fix

**The anti-clobber suffix works on Windows again.** `claim_base` looked up the
path registry with `str(base)`, which uses the OS's own separator, while the
engine stored `base_path` with forward slashes (`template.render` yields a
`PurePosixPath`). The two forms are the same string on Linux and macOS and
different ones on Windows, so there the lookup never found the owning row: a
second message rendering to an already-claimed path was written straight over
the first instead of being suffixed.

The registry key is now serialised with `base.as_posix()` on both sides of the
seam, which also makes an archive database portable between platforms rather
than only readable on the one that wrote it.

An archive written by v0.1.3 on Windows carries native-separator keys; the
first run after upgrading re-claims those paths under their canonical form.
