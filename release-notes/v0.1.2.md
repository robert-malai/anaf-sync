# anaf-sync 0.1.2 — an archive that survives a crash

Correctness and durability across the write path, plus the scheduling and
configuration fixes that only show up once runs are unattended.

## Fixes

**Path collisions resolve against the state file, not the filesystem.** The
engine used to probe the disk for an existing path and suffix around it, which
meant `--redownload` wrote a second copy beside the first and a crash's
leftovers were never healed — only accumulated. State now owns the base-path
claim through an ownership index, so a refresh rewrites in place and a
half-written run is reclaimed by the next one. Records store the artifacts
actually written rather than the ones the config asked for, credit notes render
under the FCN `transformare` standard, and listing entries with no message id
became a counter instead of poisoning the run's exit code.

**One sync at a time.** Overlapping scheduled passes could race the state file
and download the same message twice; `sync` now takes a `filelock`-based
single-instance lock for the whole run. The lock — not the state file — is what
serializes runs, because the state file cannot.

**`SyncState` is durable, not just written.** Mutations fsync before returning,
so a machine that loses power mid-run comes back to a state file that agrees
with the disk.

**Windows schedule intervals are exact or rejected.** `schtasks` silently
rounded what it could not express — `--every 90m` quietly became hourly. The
mapping is now exact, and anything unrepresentable is refused up front. The
systemd unit gained the `Wants=` that makes its `After=network-online.target`
actually effective.

**Scheduled runs find their credentials.** A CWD-relative `.env` is invisible to
Task Scheduler, systemd, and launchd, which never start from your folder. The
`ANAFPY_*` env file is now also read from the config directory, next to
`config.toml`, where a scheduled job can find it. A CWD `.env` and real
environment variables still win.

**`anaf-sync status` no longer crashes on a broken config** — it reports the
problem in-line, and additionally shows whether the `ANAFPY_*` credentials
resolve.

**Path sanitisation hardened** — Windows reserved device names (`CON`, `NUL`,
`COM1`, …) and a length cap per substituted value.

## Internal

`context.Direction` renamed to `DirectionLabel`, so the name no longer collides
with the config enum it is projected from.
