# anaf-sync 0.1.3 — the state file becomes a catalog

## Change

**The JSON state file is now a SQLite archive.** `state.py` becomes an
`Archive` over stdlib `sqlite3` (WAL, `synchronous=NORMAL`) that keeps doing
the dedupe job and, at the same time, records what was archived: message id,
path registry, and best-effort invoice fields (partner, date, number, total,
currency). That catalog is what a browse or search UI would read; nothing in
this release reads it yet.

Each mutating method commits one transaction before returning, so the crash
invariant is unchanged — a run that dies mid-pass has lost nothing and will
duplicate nothing. What did change is the retention model: **downloaded records
are permanent**. Past ANAF's 60-day window a message id can never be listed
again, so keeping its record forever costs nothing and makes the dedupe gate
exactly "was this id *ever* archived". Only failure traces are pruned, and they
are visibility, never a retry gate — hence `state_retention_days` is now
**`failure_retention_days`** (default 90). The state file's default name is
`state.db`.

Collision policy moved out of the engine and into `claim_base`, where the
ownership index lives; the engine no longer does storage housekeeping at all.
`anaf-sync status` opens the archive read-only. The run lock stays exactly as
it was: it serializes whole runs — artifact writes, ANAF's call quota, DB
contention — which the database cannot do for us.

**Migration:** the old JSON file is not read. An existing archive keeps its
files; the first run after upgrading rebuilds the record set by re-downloading
whatever is still inside ANAF's 60-day window, writing to the same template
paths.

## Fix

The PyPI **Homepage** URL now points at the GitHub repository.
